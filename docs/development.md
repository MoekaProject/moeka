# Development guide

Moeka is a Rust/GPUI desktop Markdown editor. This guide collects the development and maintenance rules that are easy to miss when changing the editor. For ownership and pane-state details, read [architecture.md](architecture.md); for the official release procedure, read [releasing.md](releasing.md).

## Toolchain and local builds

- Use an up-to-date stable Rust toolchain with rustfmt and Clippy. The crate uses Rust edition 2024; there is no documented minimum supported Rust version. Keep `Cargo.lock`, `vendor/gpui`, assets and test fixtures with the checkout. `alacritty_terminal` is pinned to a Git revision.
- **Use the release profile for every Cargo command that supports `--release`**: `cargo build --release`, `cargo run --release --bin moeka`, `cargo test --release`, `cargo clippy --release`, and cross-target checks. `cargo fmt` does not accept `--release`; do not add it to formatting commands. Prefer `--locked` for validation and release builds, so a check cannot silently change the lockfile.
- A normal local build does not require Apple signing, notarization or GitHub release credentials. Publishing is a separate maintainer operation; never use `make publish` as a routine build or test command.

```sh
cargo fmt --all -- --check
cargo clippy --release --locked --all-targets
cargo build --release --locked
cargo test --release --locked
cargo run --release --locked --bin moeka
```

### Platform prerequisites

- **macOS:** Install Xcode, its macOS SDK and command-line tools, and select the active developer directory. GPUI generates Clang bindings and compiles Metal shaders; on Xcode versions with separately installed Metal tooling, install that component too. Signing/notarization is only needed for distribution.
- **Windows:** Install Visual Studio C++ Build Tools and the Windows SDK with a matching Rust MSVC toolchain. The vendored GPUI release build needs SDK `fxc.exe` on `PATH` or via `GPUI_FXC_PATH`. Native builds do not need `cargo-xwin`; see [Windows cross-build notes](../packaging/windows/README.md) for the macOS cross-build path.
- **Linux:** Install a compiler, Clang, CMake, pkg-config and the relevant audio, font, TLS, Vulkan, Wayland and X11 development libraries. The package workflow uses Ubuntu 22.04; other distributions need equivalent packages. Running the app requires a graphical session and suitable graphics drivers. See [GPU diagnostics](gpu-diagnostics.md). Packaging needs additional tools such as `patchelf` and `zip`.

Use a disposable workspace for manual testing: the app's normal editing, auto-save and session persistence are active. For a fresh-clone check, record the commit, OS/architecture and toolchain, and build from tracked sources rather than copying ignored caches. An exported source snapshot lacks Git revision metadata; review and scan it separately before considering any public distribution. See [open-source readiness](open-source-readiness.md).

## Where changes belong

- `src/buffer.rs`, `src/cursor.rs`, `src/markdown.rs` and `src/table_ops.rs` own source coordinates, parsing and pure text/table transformations. Byte offsets, UTF-16 offsets, grapheme positions, source lines and display coordinates are **not interchangeable**.
- `src/editor/mod.rs` owns `EditorView`, document state, parsing and cache orchestration; `element.rs` and `helpers.rs` measure, prepaint and render visible lines, tables and previews. `input.rs` routes pointer, wheel and keyboard input. Hit areas are generated during layout and must match the rendered geometry.
- Split panes share `EditorView` through pane-state swapping. Add per-document fields to the mirrored state in `src/editor/pane.rs`; shared app state must not be mirrored. Async callbacks must validate the originating pane/tab and cancellation or epoch state before applying results. See [architecture.md](architecture.md#split-panes-state-swap-invariants).
- Preserve undo transaction boundaries, source-to-display mappings, focus and caret behavior, and incremental **and** full-parse paths. A numerical layout test does not prove that the GUI behaves correctly.

## Editor interaction invariants

### Theme colors and cached text

- Keep the 16 light and 16 dark themes distinct in canvas/chrome temperature as well as Markdown and code palettes. Retain genuine `#FFFFFF` canvases for Paper White and Studio Daylight alongside tinted alternatives; keep identifiable red, orange, yellow, green, cyan, blue and purple representatives across canvas/accent/Colorful heading, not just code tokens. Prefer coordinated, readable ink over uniformly pastel syntax or indiscriminate saturation. Theme names and stored preferences stay compatible; preserve monochrome Markdown and the optional dark sidebar independently. See [theme color guidance](themes.md).
- Colorful Markdown uses its semantic tokens (including `italic`); font/style/weight and nested inline-code precedence remain independent. Monochrome keeps opaque, readable muted ink and preserves colored links/code. Inline-code backgrounds and code-block borders use their dedicated theme tokens without another mode-specific alpha layer.
- Palette constants are authored offline in perceptual color space and stored as sRGB; do not generate or contrast-correct palettes per text run/frame. Test small Markdown text, code tokens on both code and Source canvases, and actual inline-code backgrounds at 4.5:1; composite alpha before measuring contrast. Keep code frames quiet and test perceptual palette distance, not just unequal RGB integers. Light-theme code also needs its own keyword/operator/string/function chromatic-distance and multi-role checks across all pairs; surface/Markdown variation must not conceal repeated code palettes.
- Global theme/font/scale invalidation must drop cached shaped text in **all** pane slots and inactive tabs, including state parked during `with_pane`. Stored panes reset geometry lazily once on restoration; never clear a million-entry cache by refilling every row on each swap. Syntax caches must include the full palette in their key. Pure tests do not replace native split-pane/theme-switch checks.

### Document modes

- The document-mode control cycles **Edit → Reading → Source → Edit**. Its localized tooltip describes both the current mode and the next click action via `i18n::document_mode_tooltip` using `edit`, `reading` or `source`; unknown keys fall back to Edit.
- Source uses the Markdown editor, with all syntax expanded as if selected, but without changing the actual selection or cursor. Keep Markdown typography for headings, lists and inline styles; do not route Source through the code editor or whole-document monospace highlighting. Reuse the code editor's line-number/fold gutter and horizontal scrolling, while retaining language-aware syntax highlighting for raw table syntax, code, diagrams and math. Show tables, Front Matter, images, code blocks, math and diagrams as literal source rows without rich block presentation. Canonical Markdown parser metadata must stay separate from presentation so incremental/lazy reparses retain block context. Paint, measurement, hit testing, selection, caret and IME must agree on source geometry. Source content is left aligned as a presentation override; never overwrite the per-tab alignment preference, which must apply again after leaving Source.
- Source keeps the outline panel/rail and Markdown-aware heading/block folds; use canonical metadata and cached structural boundaries so literal headings inside code/math never appear in the outline. Its alignment control toggles auto-wrap instead; persist `source_word_wrap` independently of the Markdown alignment preference, defaulting to true for new and legacy sessions.
- Source input uses `source_edit`'s pure plans and `source_input`'s atomic batches for Markdown delimiter completion/upgrades, matching-closer skipping, exact literal selection wrapping, paired Backspace/forward Delete rollback and structural Enter/Backspace. Continue ordered/unordered/task lists and quotes locally; preserve source indentation for code, math and YAML. Respect escaped syntax and literal code/math, YAML, HTML and link destinations; never run rich table autoformatting, list-wide renumbering or rendered table/Front Matter transformations in Source.
- Plan every Source caret against the same original buffer. Merge overlapping selections/duplicate targets before mutations, preserve primary identity and selection direction, and fall back to literal edits when assisted plans conflict. Resolve native explicit/marked IME ranges before normalization, preserve their character boundaries rather than snapping them to editor-caret graphemes, and keep surviving extra cursors aligned with their marked ranges. Paste, Shift+Enter and native composition/replacement callbacks remain literal, including single-character input; do not route them through pairing/wrapping assistance. Internal segmented paste preserves independent segment assignments; merged overlapping clusters insert identical segments once or join differing segments in clipboard order. Keep one undo boundary and one reparse per action. Index cumulative edit effects once so cursor/anchor remapping uses binary queries rather than repeated prefix scans.
- Source assistance shares sparse syntax-context checkpoints (every 64 lines); invalidate from the earliest affected line before mutation and retain only proven unchanged prefix checkpoints. Use current-line prefix scans rather than temporary prefix buffers. Delimiter lookbehind is bounded to 256 lines/64 KiB/256 context queries and speculative fence lookahead to 256 lines; decline uncertain completion/skipping rather than repeatedly scanning the document. Whole-buffer replacement, session restore and unrelated reparse paths must still clear stale context.
- Mode changes anchor the caret's visual row to its previous screen height, accounting for wrapping and rendered tables/previews. If the caret is offscreen, preserve a viewport anchor instead of scrolling to it. Reconcile a bounded number of layouts; newer scrolling, navigation, edits and tab changes must cancel stale anchors.
- Mode-switch prepaint reconciles measured scrolling in a retryable GPUI transaction, with at most three passes per frame. Keep measurements across rejected attempts, but publish paint, hit areas, caret and menu geometry only from the accepted pass; never paint an estimated offset and correct it next frame. Count anchor confirmations per accepted frame, not per attempt. Prepare generated previews once per frame, keep synchronous follow-up work bounded even alongside async images, and wait for genuinely in-flight resources without polling.
- Persist document mode per tab and mirror it in pane state, preserving Source through tab/pane switches and session restore. Saved sessions without the new mode field must remain readable and retain their legacy Edit/Reading behavior; do not turn mode into a shared global preference.

### Formatting and tables

- Collapsed unordered-list markers align their visible glyph edge (not the font advance cell) with the content left edge at the top level and the parent text left edge at nested levels. Correct only the marker's paint origin; preserve prefix advances, wrapped-text indentation, source mappings and caret geometry. The same marker paint helper serves normal lines, table cells and removed diff rows.
- CJK-adjacent punctuation flanking is a source-byte-preserving inline extension shared by display and export. Keep pulldown's pairing/nesting and Western intraword-underscore rules, and leave code, math, raw HTML, URI/link destinations and reference keys untouched. Restore original text before export; self-labelled shortcut/collapsed references must retain their original lookup identity, including inherited table-cell definitions. Never resolve an unknown reference using a rewritten sentinel key.
- Table-cell lists use one source-mapped fragment per accepted `<br>` (not tags inside code, opaque inline math/scripts or Wiki targets). First and later fragments share marker folding, monospace prefix advances, paint, caret/selection and IME geometry. Never trim reserved list-prefix padding; reserve the checkbox plus gap using the measured monospace advance and tracking. If a prefix cannot fit on one soft row, reveal its original source consistently in paint/input rather than drawing a marker across neighboring cells. Incomplete `1.`, `- [ ]` and `- [x]` stay literal, including when unfocused; only real following source whitespace completes a marker. Rendering retains actual trailing cell whitespace without changing semantic table parsing or serialization. Checked-task strikethrough ends at its own fragment boundary and must not suppress explicit inline strikethrough elsewhere.
- Table-cell inline syntax activation uses complete primary/extra selections and every IME marked range, projected and clipped into the owning cell, not just cursor endpoints. Match ordinary editor drag stability: reveal a token only when both drag endpoints are inside its trigger; reveal intersected syntax after selection commits. Respect reading/read-only modes and empty-drag suppression. Painting, measurement and native input must share activation, configured script/footnote scales and UTF-8-safe source/display maps. Trim real source padding only, never synthetic script/footnote placeholders. Keep whole-cell inline ranges when painting backgrounds across accepted breaks; reparsing fragments loses cross-break emphasis/highlights.
- Cell parsing resolves document reference links before custom inline syntax and retains authoritative semantic-cell navigation metadata after protected pipes. Cmd-hover/click for links, WikiLinks and defined footnotes follows ordinary editor precedence and source visibility. Accepted breaks alone are atomic for horizontal movement/deletion; escaped or opaque tags remain ordinary text. Home/End and their selection variants stay within the cell, including extra cursors. Reject row-wide heading/quote/fence/rule formatting inside rendered cells rather than corrupting table syntax; list/task formatting stays fragment-local. Checkbox hit height follows its actual first soft-row height, including tall formulas.
- Rendered-cell Enter continues unordered/ordered/task lists within accepted fragments, resets new tasks to unchecked, and outdents/exits empty items like ordinary editing. Shift+Enter, Ctrl-O and native/pasted/IME newlines insert soft `<br>` without list continuation, including the final fragment and real trailing whitespace. Tab/Shift+Tab indent list fragments before cell navigation; ordered renumbering stays cell-local. Uppercase `[X]` and lowercase `[x]` share task behavior. Preserve the entire replacement inside one cell; use the same source range for navigation, caret/IME geometry, multi-cursor edits and native input callbacks. Keep literal source-table/YAML input and explicit outside-table boundaries separate. Resolve/remap native UTF-16 targets before materializing a boundary line, rather than letting a stale EOF range edit the last cell.
- First-fragment list extraction treats only one optional ASCII space immediately after a pipe as formatting padding, retaining further spaces/tabs as list indentation; later `<br>` fragments have no pipe padding. Compact `|- item|` gains one formatting space on first Tab. Repeated indent/outdent must preserve semantic depth, and input lookup must use these rendered ranges rather than trimmed parser starts. Share measured hanging soft-wrap geometry across paint, selection, caret, hit testing, vertical navigation and IME; retain actual soft-row heights for tall math. Prefixes too wide for their lane fall back to wrapped source rather than crossing cell borders.
- Backspace/Delete, word deletion, line-boundary deletion and Delete Line operate on semantic cell fragments, not physical pipe-delimited rows. Merge overlapping multi-cursor deletions and remap all selections together. Accepted breaks delete atomically; cross-cell selections, separators and edits exposing escaped/code-protected pipes are protected no-ops. Validate combined row topology so several individually safe deletions cannot change neighbouring columns. Inline pairing uses fragment-local context.
- Markdown column widths use the maximum inactive rendered hard-line advance in each column, including bold headers, CJK fallback, tracking, list prefixes and exact cached-math widths. Do not count hidden Markdown targets, `<br>` tags or actual trailing source padding; synthetic script/footnote spaces still reserve visible content. Keep short columns at their natural width, distribute constrained space among the remaining long columns, and give surplus only to the widest columns. Rewrap rows after assigning widths and use those same cell bounds for painting, hit testing and IME; opening inline source syntax must not resize columns. Preserve Front Matter's separate key/value sizing rules.
- The formatting toolbar outside the content is available without a settings toggle; do not restore the old `format_toolbar_visible` preference or an inline floating formatting toolbar. Legacy saved values of that preference are ignored. Formatting controls and the table handle must not obscure the editing caret or steal a drag gesture.
- A table cell and a row/column handle right-click render through the **same table-menu path**, with the same ordering and width. Their action targets differ: a cell uses its rectangular selection when the clicked cell belongs to it; a handle uses its row/column segment selection. Preserve copy/cut, insert/overwrite paste, clearing, alignment, insertion and deletion on both paths. Front Matter supports only actions appropriate to its key/value structure; do not route its cell contents through Markdown-table serialization. Reject unsupported nested or comment rows rather than rewriting them incorrectly.

- On multi-cell selection, **insert above/left relative to the first selected cell and below/right relative to the last**. Handle multi-selection uses its first/last selected segment on the relevant axis. Clearing cell contents must not turn into deletion of an entire row or column; structural deletion remains a separate action. Keep source-table mode, selection and undo/redo consistent when editing pipes, alignment rows or whole cells.
- Reading/read-only modes never paint table editing handles, register their hit targets or show a hand cursor, even with stale hover/selection state. Entering reading mode cancels pending handle presses/drags and structural selections without discarding ordinary text selections.
- A handle click selects a row or column; Shift extends a contiguous range and Cmd/Ctrl toggles segments. Hold-and-drag reorders selected segments. Test right-clicks on selected and unselected segments, rectangular cell selections, header cells, Front Matter, noncontiguous selections and destructive operations in split panes.

### YAML Front Matter

- Rendering is a source-preserving view: typed scalar controls and date displays use parser-provided source ranges, remain opaque to Markdown inline syntax, and expand to original YAML consistently for editing, hit testing and IME. Scalar toggles replace only their unquoted token in one undo transaction; comments, quotes and surrounding YAML stay unchanged. Keep metadata and hidden-line geometry consistent across full, incremental and lazy parsing, and invalidate layout when focus or date formatting changes.
- Metadata columns use the actual shaped key/colon widths (including bold, CJK fallback and letter spacing), not character counts or spaces as a pixel-width estimate. `editor::front_matter_layout` stretches only synthetic display padding, keeps source maps intact, and shares the final glyph positions across painting, soft-row segments, caret/IME and hit testing. Wrap the value alone with a hanging indent; oversized keys stack values below their wrapped label, and width-constrained list/multiline groups remain source-visible. Boolean placeholders reserve the checkbox's actual pixel width plus its gap. Re-measure after source/font/scale changes and keep measured columns pane-local.
- Use `app_settings.date_time_format` for timestamps and its date component for date-only values; never invent a displayed midnight for missing time fields. Retain supplied timezone offsets and fall back to source on invalid dates/formats. Actual midnight timestamps still use the full date/time format.
- Property-type icons share a leading column in paint and input/IME layout, align their visible SVG ink to its left edge (compensating intrinsic asset whitespace), use the default cursor, and highlight only their foreground accent on hover, with no background or tooltip. Text, multiline text and empty values share the text icon; numbers use the dedicated calendar-month asset. Type menus have no header and size to their localized labels, icons and checkmark rather than inheriting the wider formatting-menu minimum. Their edits validate the originating pane, tab and source and replace only the owned YAML value/subtree in one undo transaction. Preserve compatible data; an incompatible conversion clears it and inserts valid target base syntax. Ambiguous source ownership and removal of an anchor referenced outside the subtree remain protected. Preserve comments, CRLF, sibling keys and root anchors, and do not silently retarget aliases to an earlier definition with the same name. Block-scalar ownership follows its explicit/inferred content indentation, not merely its key indentation; scalar contents must not be scanned as new YAML nodes.
- Multiline and simple-list values expand as an owning property group when any member gains a caret, selection or IME range; unrelated values stay independent, while focus anywhere in Front Matter reveals both YAML delimiters together. Keep the value column stable between focus states for values and indented body rows; a truly empty body row (no indentation) stays raw so its caret and typed text share column zero, and text typed there becomes a column-zero key. Collapse inactive block-scalar syntax rows while retaining their key/icon, and fade the expanded block indicator. Render inactive simple lists on one horizontally scrollable row with source-mapped item hits and tightly spaced removal controls. Single-line flow sequences `[...]` and flow mappings `{k: v}` share that row form; each mapping entry is one `key: value` item, and removing an entry or the last one (`{}`/`[]`) is one exact source replacement. Nested, multiline, anchored or otherwise complex flow syntax stays source-visible. Item removal is one undo transaction, preserves comments/CRLF and changes the last item to `[]`. Invalidate group geometry and stable IME anchors immediately on focus changes, and keep unsupported, commented or width-constrained lists source-visible instead of hiding content. When the whole front matter is not valid YAML, decoding is decided per top-level entry, so an incomplete sibling leaves its neighbours' typed values and groups rendered; valid documents keep whole-document decoding (including cross-entry aliases).
- Enter and Shift+Enter route through YAML planning before Markdown-table handling: preserve block-scalar indentation, continue block lists with `- `, and safely split quoted values. Empty/null sequence items retain aligned value metadata before typing. Single-cursor Backspace on empty multiline/list continuation rows removes structural indentation/markers/empty quotes atomically and returns to the preceding line's end; preserve comments and explicit nonempty/null tokens, retain `[]` when removing the last list item, and include Enter-created trailing indented plain-scalar blanks without claiming sibling trivia. Empty/comment-only metadata supports safe source EOL breaks. Apply multi-cursor batches atomically, preserve CRLF and IME offsets, and reject overlapping or unsupported edits rather than inserting Markdown/HTML syntax into YAML.
- Typing `:` at the end of a key slot (a bare row inside front matter, including the first key of an empty block) inserts `: ` in one edit so the value can be typed immediately; body text, sequence rows, blank rows and mid-line colons are never rewritten. The rule is decided from the pre-edit decorations and `---` lexing via `editor::front_matter::key_colon_needs_space`.
- Whole-block folding hides only the interior rows; the opening delimiter row keeps its measured height and is transparent while unfocused; the closing delimiter row is removed from the layout while unfocused and reappears with focus, so its geometry follows focus through the front-matter focus signature and caret/IME anchors only exist while it is visible. The collapsed summary (localized top-level entry count) sits on the first body row with the List-type icon and carries the fold control; empty metadata has no body row, so its summary stays on the opening row. Apart from that case, the opening row draws no gutter fold icon; the carried control is the only fold affordance. Fold ownership remains section 0 in source. Both delimiters align to the editor content-left edge rather than the type-icon inset; caret, selection or IME focus anywhere in the metadata makes both delimiter rows visible at once. A collapsed block cannot hold the caret: hidden carets move to the opening row's end or past the closing row. Keep the upper-left fold control attached to the first visible property when expanded, reveal it on row/button hover using the heading-style opacity behavior, and reserve its slot beside the formatting trigger so the formatting button stays to its left. Preserve selections over folded source, reconcile hidden carets/IME before exposing input geometry, cancel native composition outside the editor borrow, and guard stale range-less callbacks so they cannot write into the relocated opening delimiter. Mirror cancellation state and hit areas in pane state.

### In-buffer search

- The current nonempty UTF-8 source match is an independent presentation range, not a text selection or edit permission. Reveal intersecting inline syntax, table-cell tokens, Front Matter property groups, code fences and generated Mermaid/math source even in reading or embedded read-only views; ordinary selections must still respect their existing expansion restrictions. Painting, measurement, hit testing and native input must use the same clipped source ranges and source/display maps. Highlight the actual keyword, not a rendered preview placeholder. Query changes, next/previous, dismissal and document edits must invalidate the prior search presentation, including transferred offscreen layout and native caret geometry.
- Before moving the search caret, finish/cancel any old native composition through the pane-local stale-callback barrier, parse the target's lazy decorations and unfold only source containers intersecting the whole half-open match. Resolve heading ownership across unparsed chunks without mistaking headings inside code, math or YAML for section boundaries. Then invalidate layout and center the actual matched soft row: bootstrap an unmeasured target into the windowed viewport, recompute after source expansion/wrapping and allow visible previews to settle. New navigation, clicks, edits or wheel scrolling supersede old confirmation; passive preview refreshes do not. Async navigation validates its epoch, pane, tab and cursor.
- Cancel sliced scans on every document reparse, including equal-byte-length edits, not only on buffer-length changes. Never append old-query or old-document ranges after a replacement or edit. Validate Chinese/emoji, multiline boundary matches, hidden link targets, table cells, folded sections, formulas and Mermaid, rapid next/previous, clear/dismiss/reopen, read-only panes and long lazy documents. Unit source-map/geometry tests do not replace native GUI checks.

### Outline, scrolling and generated previews

- The outline panel can be manually resized to 10 logical pixels (following editor zoom); keep its default content-based preferred width separate from this minimum. Narrow content must shrink and clip rather than impose a larger flex minimum. All panel scrollbars share idle fading: do not impose a panel-specific opacity floor. Reveal on scroll, hover or drag, and reconcile hover against the clipped track bounds when a drag ends outside the track.
- Outline navigation must scroll to the **measured heading position**, not just a source-line estimate: lazy chart/math rendering and line wrapping can change measured heights. Allow visible lazy previews to settle before confirming navigation. User scrolling or a newer navigation cancels the old animation/confirmation; a preview refresh must not cancel the active outline navigation.
- The active outline item and outline rail should agree and track the section at the top of the editor viewport, with a short clicked-heading override while the caret remains on that heading. Editing body text without changing heading syntax must not make the indicator flip merely because the caret moved. Invalidate the outline index after lazy-document edits, not just after obvious heading edits. Exercise long documents with many charts, headings, folds and different scroll heights.
- Lazy Mermaid/math previews keep the previous image as a layout placeholder during refresh. When their measured height changes above the viewport, prepaint compensates for the difference. Wheel input cancels stale pending preview-reveal and click-anchor restoration; never replay an older scroll offset after a newer user scroll. Check for vertical jitter while scrolling through multiple lazy previews.
- Block math is enlarged relative to its former size by 1.5×; inline math uses its intrinsic logical size (excluding the math raster's 3× resolution), is vertically centered within its **soft-wrapped row**, and expands only that row's height to fit its tallest collapsed formula. Other rows of the same source line keep their own measured heights; table cells measure rows independently. Layout, paint, scrolling, selection, caret, hit testing and IME geometry must use the same per-row heights and cumulative offsets, not a source-line-wide maximum. Expanded formula source and uncached formulas retain the normal text line height. Inline formula advances match the intrinsic width exactly, with no added horizontal padding or margin; preserve spaces explicitly present in the source. Keep placeholder widths, paint, hit testing and IME geometry in sync. Mermaid retains its general text size, with larger **sequence diagram** labels/messages. Do not globally enlarge all diagram text. Fullscreen Mermaid initially occupies roughly 80% of the padded viewport; rendering and pan clamps use the same inset, and the chart is clipped to that area. Clicking a non-button location closes fullscreen **only when it was a click**; dragging pans without closing it. Buttons still perform their own actions. Recheck fullscreen over tabs, sidebars and split panes.

### Document exports

- `editor::info_panel::ExportLayout` snapshots the normalized “Editor content width” setting, independent of current pane bounds or editor zoom. HTML and PNG reserve that exact usable width plus separate page margins; narrower browser windows may adapt responsively. PDF pages grow with the configured width instead of forcing A4 wrapping. WebKit measures and slices at the configured CSS-pixel content width; CoreGraphics converts slices, page dimensions and margins consistently at 72/96 points per CSS pixel. PNG snapshot widths compensate for the host window's backing scale to target 2x pixel output, not 4x on Retina. The non-macOS plain-text PDF fallback uses the same page geometry and width-based wrapping; it is not a rich HTML renderer.
- Export math follows editor-owned preview ranges for bracket blocks and dollar blocks spanning blank paragraphs, adapting unsupported parser forms into safely fenced math without rewriting code or raw HTML literals. Display math, inline math and fenced previews stay opaque to custom-syntax escape masking, including TeX spacing commands such as `\\:`. Test actual math SVG paths and absence of error previews, not merely an `<svg>` tag. Unit geometry/composition checks do not substitute for native WebKit PDF/PNG visual verification.

### Other input and background work

- Fenced-code input, selection, IME, cursor reveal and wrapping share source/display mapping; do not reset scrolling to the caret on unrelated preview refreshes. Explicit wheel scrolling takes priority over pending typing-scroll restoration.
- The file watcher covers open documents even without a workspace and tracks parent directories so atomic external replacement remains visible. Never overwrite dirty tabs with an external reload. Background file operations should not block GPUI; late results must be checked against the current pane/tab before modifying contents.
- Block dragging operates on Markdown blocks, including folded sections, nested lists, code fences, tables, Front Matter and generated previews. Preserve indentation, list renumbering and blank-line separators in one undo transaction. Escape, document switches and content edits cancel the gesture. Exercise dragging after scrolling and across wrapped lines; see `editor::line_drag::tests`.

### Unavailable mounted workspaces

- Treat every workspace path as potentially blocking, including `exists`, `is_file`, `is_dir`, metadata, canonicalization, native bookmark resolution and watcher registration/destruction. Render, prepaint, navigation, tab comparisons and launch URL decoding must remain filesystem-free. Classify supplied document bytes without reopening files. Use embedded help/icon assets during startup, not the process working directory.
- `src/platform/fs_task.rs` isolates mount-sensitive work from GPUI's executor: a five-second default deadline, an independent watchdog, at most 32 live workers and four per lexically identified workspace/scope, nonblocking admission queueing while active workers are still within their deadlines, and immediate duplicate/capacity rejection once a worker or scope is stalled. Register workspace roots without probing them. An expired or cancelled job retains its slot until its actual work and cleanup finish; abandoned result destructors must run on that worker, never the UI or watchdog. Do not replace a stuck worker with unlimited new threads or put blocking locks/joins on UI.
- A timeout bounds application waiting, **not the kernel operation**. Writes, moves, deletes and Git mutations may finish later. Preserve dirty buffers and local recovery, do not mark saved/close/change Save As targets without confirmed current success, and do not automatically retry an uncertain mutation. Serialize saves without parking workers behind a stalled path; pause autosave after uncertain writes until an explicit save succeeds. Check deadlines between phases, especially after metadata/volume probes and before fallback writes, cleanup or source deletion. Preserve the existing inode/symlink semantics of document saving.
- Restore workspace/tab/pane metadata before source I/O, then hydrate asynchronously by stable identity. Keep original pending records, view/history metadata and recovery when a source is unavailable; never persist blank loading snapshots over saved records or attach an unverified recovery draft to an automatic source write. Ignore stale hydration after edits, Save As, tab closure or pane changes. Shutdown session flush is bounded.
- Watcher services retain native state off UI, use bounded nonblocking event delivery and independent per-service locks, and reconcile after discarded batches. Observation errors distinguish confirmed `NotFound` from unavailable/permission/timeout; do not turn a failed observation into file deletion. Failed directory/search/Git refreshes retain previous contents and clear loading state. Apply root/epoch guards and suppress repeated passive errors. Traversal skips descendant symlink cycles but permits an explicitly selected hidden/symlink workspace root.
- Surface operation, path and original OS cause (or explicit application timeout) through the bottom-right notifications. Native open/reveal path validation is bounded; on macOS construct file URLs with explicit directory hints rather than implicit filesystem probes. A native reveal acknowledgement confirms dispatch, not Finder's eventual selection.

Manual verification requires disposable local and actual SMB/sshfs workspaces: restore multiple panes with an offline mount, stall a read/listing/save while editing another local document, switch roots during pending work, confirm error toasts and unchanged dirty/recovery state, reconnect and retry explicitly, and check create/rename/copy/delete/export and watcher recovery. Injected blocked-worker tests establish application containment, not platform-specific kernel cancellation or a real network-outage reproduction.

### Safe filesystem deletion

- `src/platform/trash.rs` owns deletion policy for sidebar deletes and the source-removal step of copy-then-delete moves. **Only positively identified network volumes bypass Trash**: macOS uses `statfs`'s non-local mount flag, Linux recognizes network filesystem types (SMB/CIFS/SMB2, NFS, AFS, Coda, Ceph and 9P), and Windows recognizes UNC paths and `DRIVE_REMOTE` (including mapped SMB drives). Generic Linux FUSE is ambiguous and must not authorize permanent deletion merely because it might be sshfs.
- Local or unrecognized filesystem types use native Trash. Failed volume probes stop deletion; permission errors, sharing violations, unsupported-operation codes, aborted operations, localized messages and unknown Trash failures **never trigger a permanent-delete fallback**. Report the error without retrying source deletion. If copying fails, clean up only a destination this operation actually created, not an existing or dangling destination link. If source removal fails after a successful copy, **retain the complete destination for recovery**: recursive network deletion or native Trash may have partially removed the source already. This can leave duplicates, which is safer than deleting the only complete copy; report its destination path. Never reinterpret the source-deletion error in the sidebar.
- Resolve ancestors without following the final symlink. Classify a symlink using its containing volume, and unlink the link rather than its target, including dangling and Windows directory links. Reject empty, root, current-directory and parent-directory targets before normalization. Recursive permanent removal must not follow links within the tree.
- Windows Trash runs on a **fresh Rust thread**, not GPUI's WinRT background-pool thread: `trash` initializes STA COM and can panic during COM initialization or object creation. Joining the worker converts ordinary Rust unwinding panics into errors without crossing the pool's FFI callback. This is not containment for native access violations, aborts or hangs, and is not evidence that a reported Windows 11 crash has been reproduced or resolved.
- Use disposable fixtures for native checks. Manually verify SMB/UNC and mapped-drive deletion, local Recycle Bin recovery, locked-file failures and directory/dangling-link safety on Windows; cross-compilation and injected-error tests do not establish native runtime behavior.

## Tests and manual verification

Run the narrowest relevant tests first, then the broader release suite. Examples:

```sh
cargo test --release --locked table
cargo test --release --locked front_matter
cargo test --release --locked editor::outline::tests
cargo test --release --locked editor::info_panel::tests
cargo test --release --locked generated_math
cargo test --release --locked generated_mermaid
cargo test --release --locked editor::preview_overlay::tests
cargo test --release --locked editor::line_drag::tests
cargo test --release --locked editor::file_watch::tests
cargo test --release --locked platform::fs_task::tests
cargo test --release --locked editor::session_store::tests
cargo test --release --locked platform::trash::tests
cargo test --release --locked editor::sidebar_files::tests
make test-publish-release
```

`cargo fmt` is the exception to the `--release` rule. The native filesystem-watcher integration test can time out on some machines; report that explicitly if it does. Skipping just that named test for a local diagnostic run is **not** equivalent to a clean full-suite pass. Unit tests do not substitute for GUI mouse, IME, split-pane, long-document, platform and save/reopen checks. Include failures and untested paths in the handoff.

GitHub Actions definitions are useful references, but **Actions are neither the official publishing entry point nor a technical gate enforced by `make publish`**. Do not infer local build or release status from an Actions run, and do not claim CI passed unless that exact commit actually passed. Use local release-mode checks and the explicit publishing preflight below. This does not waive human distribution/licensing review.

## Official publishing: local and deliberate

Only maintainers publish binaries, from the macOS signing machine, to `MoekaProject/community`. Application source and its tag stay in the private `MoekaProject/moeka` repository. The public community tag refers to *community's own* `main` commit; never push the application's private Git history to the public repository. **Never republish or modify `v0.1.12`.** Read [releasing.md](releasing.md) for signing, notarization, artifacts, required human licensing/source review and safe retries. The unchecked items in [open-source-readiness.md](open-source-readiness.md) are not automatically cleared by a successful build or publish command.

1. Review the release contents and version. Update `Cargo.toml` **and** the `moeka` entry in `Cargo.lock`. Run local release-mode validation and complete the relevant human review.
2. Commit the intended changes and synchronize `main` with `origin/main` through the normal process. Publishing never commits or pushes `main` for you. Verify the destination repository and push URL before pushing.
3. Run `make publish-check TAG=vX.Y.Z`. It is read-only and requires a completely clean tree, a version-matching tag, `main` tracking the current live `origin/main`, required distribution files, and authenticated release-repository write access.
4. When publishing a **new** release, run `make publish vX.Y.Z` (or `make publish-beta vX.Y.Z` for a prerelease). The command performs signing/notarization, cross-platform packaging, safe tag/draft handling and asset verification. It can take a long time and changes remote state; do not invoke it to inspect release status. A published release is immutable to this helper. If a maintainer already ran the command, **verify instead of rerunning blindly**:

```sh
git ls-remote origin refs/tags/vX.Y.Z
gh release view vX.Y.Z -R MoekaProject/community
```

A successful local `make publish-check`, a version bump, a claim that the command was run, or a draft is **not** proof of a published release: verify the public release and its assets. On failure, preserve the original `dist` files and inspect any existing tags/draft before retrying; never force-push, delete or overwrite a released tag or asset to make a check pass. GitHub Actions results are not a prerequisite in the `make publish` implementation; follow the human review and retry requirements in [releasing.md](releasing.md).

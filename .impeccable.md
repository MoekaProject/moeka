## Design Context

### Users
Moeka serves writers, researchers, knowledge workers, and developers who edit local Markdown for long sessions across notes, documentation, code, diagrams, and structured content.

### Brand Personality
Refined, calm, capable. The interface should feel native and focused, with enough character to be memorable without competing with the document.

### Aesthetic Direction
Use a curated set of 16 built-in themes. Light themes are the priority and should cover quiet editorial, warm paper, and precise modern IDE directions. Dark themes should retain their current strengths while gaining more consistent surfaces, borders, contrast, and semantic color hierarchy. Theme names and persisted compatibility with the previous catalog are not constraints.

### Design Principles
- The document is the visual focus; chrome stays quieter than content.
- Every theme needs distinct neutrals, not only swapped accent colors.
- Light themes avoid pure white, weak gray-on-white text, and muddy borders.
- Accent colors communicate hierarchy and semantics with restraint.
- Text, controls, selections, diffs, code, and Markdown syntax must remain accessible and coherent as one system.
